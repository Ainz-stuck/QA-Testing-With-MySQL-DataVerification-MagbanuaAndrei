# QAT Toolkit: Kara David's Wish Note

## Repository Overview

This QAT (Quality Assurance Testing) toolkit documents the functional testing of an AI-generated web application. The source test case is also kept in the plain-text file `textcase.txt`.

This repository contains three parts:

- **Part A:** This README file, containing the test case for the AI-generated web application
- **Part B:** The AI prompt used to create the test web application, named `webapp-generation-prompt.txt`
- **Part C:** The single-file PHP web application generated by AI, named `test-webapp.php`

## Test Case Documentation

| Field | Details |
|---|---|
| **Test Case ID** | TC-DataEntry-001 |
| **Test Case Title** | Data Entry - Valid |
| **Description** | Functional testing of the Data Entry page with backend validation using MySQL queries |
| **Preconditions** | Kara David Birthday Wishnote App is installed locally and the MySQL database is pre-populated for comparison. The Data Entry page is accessed in the latest Chrome/Firefox browser. |
| **Test Data** | Five (5) valid entries containing First Name, Last Name, Government Position, and Location, each within its maximum character limit |
| **Status** | **Failed** (Step i: Location is not saved to the database) |

## Test Execution Table

| Step | Action | Expected Result | Actual Result |
|---|---|---|---|
| a | Verify that the form contains labels in proper order and the text boxes are writable | Labels appear in this order: "Target's First Name", "Target's Last Name", "Target's Government Position", "Target's Location"; all text boxes are writable | Labels appear in the expected order; all text boxes are writable |
| b | Verify the "Send Wish Note" button | The button changes color on hover and is not disabled | The button changes color on hover and is not disabled |
| c | Enter test data on their respective fields | The fields accept valid test data | The fields accept valid test data |
| d | Click "Send Wish Note" | A centered "Verify Target Data" modal appears | The modal appeared centered on the screen |
| e | Verify the modal contents against the test data | The modal shows the same First Name, Last Name, Government Position and Location entered | The modal matched the test data |
| f | Click the Cancel button | The modal closes, the form keeps its data, and nothing is saved | The modal closed; the form data stayed; nothing was saved |
| g | Click "Send Wish Note" again, then click "Confirm and Send" | The form is submitted | The form was submitted |
| h | Verify a successful entry message shows on the Data Entry page | "Success! The wish note has been sent." shows above the form | The success message showed above the form |
| i | Verify the test data in the database | All four values are stored for each of the five entries | Only FirstName, LastName and GovPosition were stored; Location is missing (see query below) |

### Database Verification Query (Step i)

```sql
USE birthday_wishnote;
SELECT * FROM main_corrupt_politicians;
```

## Defect Summary

The web application intentionally omits the `Location` column from both the `INSERT INTO` statement and `bind_param()`. Entries are saved without a location, so Test Case TC-DataEntry-001 **fails** at Step i.
